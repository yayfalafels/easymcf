# Validation Utilities - Feature tracker
>Review the guidelines before performing any actions including edits on the document

## 010.12 (closed) validation utilities

Closes the concrete gaps in the backend and frontend validation tooling an autonomous Claude AI agent uses to drive and check this app's own API and UI during implementation and validation, so milestones 09-11 each validate their own golden path through a shared, structured-logging harness rather than one-off `curl`/manual-click checks reinvented per milestone. Reuses, rather than replaces, what milestone 07 already built: extends `scripts/api_tester.py`'s existing ad hoc/single-case-replay mode with batch replay, a three-way `PASS`/`FAIL`/`ERROR` verdict, and structured log output, per `STRAT-SILO-03`; and adds one new thin script, `scripts/ui_tester.py`, built directly on `tests/_browser_support.py`'s existing `spawn_app`/`terminate_app` process-lifecycle helpers, for the one capability that doesn't yet exist — a standalone, non-pytest way to drive the `tests/frontend`/`tests/e2e` Playwright tiers' own DOM-assertion convention (`ARCH-TEST-09`).

## Scope

**Reuse-first mandate**: milestone 07 already delivered most of the raw material this milestone needs — `scripts/api_tester.py` (ad hoc request + single-case replay against a running instance, `[PASS]`/`[FAIL]` output, `STRAT-SILO-03`) and `tests/_browser_support.py` (`spawn_app`/`terminate_app`, plain functions that start `python -m easymcf` on an ephemeral port and poll `/api/v1/health` until ready, already shared by the `tests/frontend`/`tests/e2e` pytest tiers). This milestone's job is to **extend `api_tester.py` in place** to close its actual gaps below, and to **add one new thin script, `scripts/ui_tester.py`**, built directly on `spawn_app`/`terminate_app` plus a bare `sync_playwright()` call, for the one capability that genuinely doesn't exist yet: a standalone, non-pytest way to drive the frontend. Nothing here forks or duplicates the pytest tiers, the case-config idea, or the process-spawn logic — every piece of existing infrastructure is read first and reused verbatim wherever it already does the job.

**what `api_tester.py` already does, verified by reading it directly** (so this isn't re-derived from the test-strategy doc's earlier, more elaborate `expect`/`req_id`/`body_contains`/JSON-path sketch, which was never actually built): ad hoc `METHOD PATH [BODY]` requests against a live instance; `--case FILE --name NAME` replay of one named case from a `tests/backend/cases/*.json` file; each case checked by an exact `expected_status` and exact `expected_body` equality (not a JSON-path or substring match); a `[PASS]`/`[FAIL]` line per case; a distinct "request error" message for a connection failure, though it is still returned as a plain `FAIL` rather than a separate outcome class; output to stdout/stderr only, no log file.

**actual gaps this milestone closes, in `api_tester.py` itself**:

- **batch mode**: `--case FILE` with no `--name` runs every case in the file, not only one named case, so a whole case file is one command rather than one invocation per case
- **three-way outcome, not two**: a request-level failure (connection refused, timeout, non-JSON body where JSON was expected) is reported as its own `ERROR` class, distinct from an assertion mismatch (`FAIL`), so an agent doesn't have to parse the message text to tell "the endpoint isn't running" from "the endpoint returned the wrong thing"
- **structured log output**: each run also writes a timestamped log file under `.dev/logs/`, per `implementation/REFERENCE.md`'s naming convention, one JSON-lines record per case (name, outcome class, expected vs. actual, timestamp, duration) alongside the existing `[PASS]`/`[FAIL]` stdout lines, so a log file is parseable without re-running anything
- **non-zero exit on any `FAIL`/`ERROR` in a batch run** — already true for the single-case path, extended to the batch path

No change to the case-file schema (`name`/`method`/`path`/`expected_status`/`expected_body`) unless `12.03`/`.04` (test strategy/cases) surfaces a concrete need milestones 09-11 would otherwise hit — a richer matcher (substring, JSON-path, headers) is not added speculatively.

**`scripts/ui_tester.py`, new, thin, built on existing pieces**:

- loads one or more UI-check definitions from a JSON config: a target route, a short sequence of Playwright actions (navigate, click, fill, wait-for-selector), and DOM-level assertions (`data-testid` element visible, text content, attribute value) — the same DOM-assertion convention `ARCH-TEST-05`/`STRAT-SILO-07` already fix for the pytest frontend/e2e tiers, made replayable standalone rather than only inside a pytest run
- process lifecycle and readiness-polling reuse `tests/_browser_support.py`'s `spawn_app`/`terminate_app` directly, unmodified — no second spawn implementation. The browser itself is a bare `sync_playwright()` call in the script, since the `browser`/`page` objects in `_browser_support.py` are pytest fixtures, not plain functions, and a standalone script has no pytest session to hang a fixture off; the launch/close code these fixtures wrap (`p.chromium.launch(...)`, `browser.new_page()`) is copied at the two lines it actually is, not abstracted into a new shared module for a single caller on each side
- runs against either the mocked-`/api` frontend silo (`tests/fixtures/api/*.json`, once one exists) or the full real-backend stack, selectable per run, mirroring the existing tier split rather than inventing a third mode
- reports the same `PASS`/`FAIL`/`ERROR` classes as the extended `api_tester.py` (`ERROR` covers page navigation failure, a `pageerror`/console exception per `07.IS.05`'s diagnostic pattern, or a locator timeout — distinct from an assertion mismatch), and on `FAIL`/`ERROR` also saves a screenshot next to the log record, since captured text alone is not always enough to diagnose a rendering defect
- writes the same JSON-lines-per-case-plus-`[PASS]`/`[FAIL]` log convention as `api_tester.py`, sharing one small log-writer helper between the two scripts rather than each formatting its own

**out of scope**

- any new business-logic test case content for search, CRM, or apply. Milestones 09-11 author their own case configs against these two scripts; this milestone's own case/check files are, at most, the existing health case plus whatever `12.06`'s mock fixtures need for self-testing
- replacing or removing the pytest tiers (`tests/backend/test_api_cases.py`, `tests/frontend/`, `tests/e2e/`) `ARCH-TEST-03/04/09` already establish, or the `tests/_browser_support.py` fixtures those tiers use directly. This milestone extends one script and adds one thin sibling for an agent's own ad hoc/iterative checking outside pytest — it is not a new automated CI-equivalent gate, and it shares the case-config idea and the spawn/poll code rather than forking either
- a general-purpose test framework, assertion library, or reporting dashboard. Scope stays the two scripts plus the one small shared log-writer
- live-MCF-site validation of any kind. Both scripts validate this app's own backend/frontend, never mycareersfuture.gov.sg directly
- process/environment preflight (`scripts/envcheck.py`), database reset/seed (`scripts/resetdb.py`), or direct-store inspection (`scripts/db_util.py`). All three already exist from milestone 07/08 and are reused, unmodified, as prerequisites a validation run assumes are already green
- CI/CD wiring, a scheduled/unattended run mode, or any cloud reporting integration — out of scope release-wide

## Design

### Shared log-record schema and log writer

One tiny module, `scripts/_val_log.py`, mirroring `tests/_browser_support.py`'s underscore-prefixed shared-helper convention (imported code, not a pytest fixture, not a package). Both `api_tester.py` and `ui_tester.py` import it rather than each formatting their own log lines.

- one JSON object per case, one line per object, appended to a log file as the run progresses: `{"ts": "<ISO-8601>", "tool": "api_tester"|"ui_tester", "case": "<case name>", "outcome": "PASS"|"FAIL"|"ERROR", "duration_ms": <int>, "expected": <value or null>, "actual": <value or null>, "detail": "<error message, null on PASS/FAIL>", "screenshot": "<path, ui_tester FAIL/ERROR only, else absent>"}`
- the existing `[PASS]`/`[FAIL]` convention stays exactly as `api_tester.py` already prints it today, unchanged, to **stdout**. The JSON-lines file is an addition, not a replacement — an agent piping stdout still sees the familiar line, and a downstream script reads the log file instead of scraping that text
- **implementation decision**: log filename carries a caller-supplied `--label` (e.g. `09.09`, matching `implementation/REFERENCE.md`'s `<feature_id>.<subfeature_id>` naming slot) rather than hardcoding `12`, since milestones 09-11 are this milestone's actual callers and each run's log should be attributable to *their* task, not to this one. `--label` defaults to `adhoc` when omitted. Filename: `<ts>-<label>-<tool>.log`, written under the existing `.dev/logs/` (already gitignored, already the convention's destination — no new directory, no `.gitignore` change)
- exit code: `0` only if every case in the run is `PASS`, non-zero otherwise — computed once, after the batch, by the calling script; `_val_log.py` itself only writes records and never decides the process exit code, keeping it a pure logging helper rather than a second place outcome policy could drift from `api_tester.py`'s/`ui_tester.py`'s own

### `scripts/api_tester.py` extension

No new file, no change to its two existing entry points' signatures (`--case FILE --name NAME` and ad hoc `METHOD PATH [BODY]` both keep working exactly as today). Additions:

- `--case FILE` **without** `--name` iterates every case in the file, calling the existing `_run_case()` for each, collecting a `(case, outcome, expected, actual, detail)` tuple per case instead of returning a single bool
- `_run_case()`'s internal branching already separates a `requests.RequestException` (connection/timeout) from a status/body mismatch — today both paths print `[FAIL]` and return `False`. The extension changes the *request-exception* path to a distinct return value the caller records as `ERROR`, and additionally: a response whose body fails `resp.json()` when the case supplies an `expected_body` is also classified `ERROR` (the case asked to compare JSON and got something that isn't JSON), not `FAIL` — a `FAIL` is reserved for "the response parsed fine and didn't match," never for "the response couldn't be interpreted at all"
- `--label` (optional, see above) and an implicit log write after the batch/case completes, via `_val_log.py`
- exit code for the batch path: `0` only if every case is `PASS`; unchanged single-case-path behavior otherwise

### `scripts/ui_tester.py` new

Structured the same way `api_tester.py` already is, so anyone who knows one knows the other: an ad hoc single-check CLI arg mode plus a `--case FILE [--name NAME]` config-replay mode.

**Check config shape** (JSON, one array per file, e.g. `tests/frontend/checks/env_status.json`):

```json
[
  {
    "name": "env-status heading renders",
    "route": "/",
    "actions": [{"op": "wait_for", "selector": "[data-testid=\"env-status-heading\"]"}],
    "expect": [{"op": "text_equals", "selector": "[data-testid=\"env-status-heading\"]", "value": "Easy MCF — local dev environment ready"}]
  }
]
```

- `actions`: an ordered list of Playwright operations run before assertion — `goto` (implicit, from `route`), `wait_for`, `click`, `fill`, each a thin dict-to-Playwright-call dispatch, no new DSL beyond naming the handful of ops the frontend/e2e tiers already use
- `expect`: DOM-level assertions only, matching `ARCH-TEST-05`'s convention exactly — `visible`, `text_equals`, `attribute_equals`, `count_equals`. Never a JS-internals check (no `window.angular...`)
- `--api-mode mocked|real` (default `real`): `mocked` spawns the app the same way and additionally registers `page.route("**/api/**", ...)` fulfilling from a `tests/fixtures/api/*.json` file if one is given, mirroring `ARCH-TEST-09`'s interception pattern; `real` runs with no interception, against the real backend and seeded database
- process/browser lifecycle: `spawn_app(db_path)`/`terminate_app(proc)` from `tests/_browser_support.py`, imported unmodified; the browser itself is `sync_playwright()` entered directly in `main()`, launched/closed around the batch, one `page` per case — not the pytest `browser`/`page` fixtures, since there is no pytest session here to register them against
- outcome classification: `PASS` (every assertion in `expect` holds), `FAIL` (the page loaded and rendered, but an assertion value doesn't match — expected/actual both captured, e.g. the actual rendered text), `ERROR` (the app process failed to become ready, `page.goto` failed, a `page.on("pageerror"/"console")` handler, wired for every check per `07.IS.05`'s diagnostic pattern, captured a JS exception, or a `wait_for`/assertion locator timed out with nothing rendered to compare against)
- on `FAIL`/`ERROR`: `page.screenshot(path=...)` before moving to the next case, saved under `.dev/logs/screenshots/<ts>-<label>-<case-slug>.png`, and that path recorded in the case's log line

**known limitation, stated rather than hidden**: `12.CK.03`'s "both mocked-`/api` and real-backend modes" can only be exercised end to end, meaning a mocked response actually diverging from a real one, once a screen exists that calls `/api/**` at all. The only page that exists as of this milestone, `env-status`, deliberately makes no API call (`07.02.02`'s own decision). Self-testing `ui_tester.py` against it, per `12.06` below, proves the `--api-mode` flag correctly wires or skips `page.route()` interception, not that interception changes what's rendered — the same honest gap `010.07`'s own `07.TC.13` noted for its degenerate oracle split. This closes once milestone 09 adds the first real screen.

### mock api and frontend fixtures — self-testing the self-test tool

**implementation decision**: no new backend route or new frontend page is built for this. Milestone 07 already ships exactly what a self-test needs, and it was deliberately built minimal and stable for this purpose (`07.02.02`: "the smallest thing that lets a human open the app... and see something real"):

- `GET /api/v1/health` (real, already returns `200 {"status": "ok"}`) — the `PASS` fixture for `api_tester.py`
- `GET /` when unmatched (the SPA-fallback rule, `ARCH-RUN-09`/`07.IS.04`, returns `index.html`'s HTML, never JSON) — the `ERROR`-non-JSON fixture, with zero new code, since this is core routing behavior rather than a coincidence of current content
- an unreachable port (the app simply not spawned there) — the `ERROR`-connection fixture for both scripts
- the `env-status` page and its `[data-testid="env-status-heading"]` element (real, already rendering the fixed text `07.02.02` specifies) — the `PASS` fixture for `ui_tester.py`

A dedicated mock Flask blueprint or a second placeholder frontend page was considered and rejected: it would add new application surface solely to serve a purpose the existing smoke-test endpoint and page already serve, reintroducing exactly the kind of duplication the Scope's reuse-first mandate rules out. The only genuinely new artifacts this task produces are **self-test config files** — a small `tests/backend/cases/selftest_api_tester.json` (one entry each for the `PASS`/`FAIL`/`ERROR` classes above, `FAIL` produced by asserting a deliberately wrong `expected_body` against the real health response) and `tests/frontend/checks/selftest_ui_tester.json` (`PASS`, `FAIL` via a deliberately wrong expected heading text, `ERROR` via a selector that doesn't exist on the page) — plus the oracle test module described in Test cases below that reads their outcomes back independently.

## Test cases

_test strategy_: four independent layers, per the tracker-pattern skill and matching `010.08`'s precedent exactly, since what is under test here is itself a checking tool, and a checker's own claim about its result is the weakest possible evidence of correctness:

1. **self-report**: the script's own `[PASS]`/`[FAIL]` stdout lines and process exit code. Proves the script ran and reached a verdict, not that the verdict is the *correct* one
2. **process boundary**: `api_tester.py`/`ui_tester.py` invoked as a subprocess exactly as an agent would run them, checking only exit code and stdout — independent of importing either script's internal functions directly
3. **direct inspection**: the written `.dev/logs/*.log` JSON-lines file, read and parsed directly, checking record shape and field values — independent of trusting the script's own stdout text
4. **oracle**: a pytest module whose expected outcome class per self-test case (`PASS`/`FAIL`/`ERROR`) is hard-coded from this Design section's own fixture descriptions above, not imported from either script's source, so a bug that makes a script misclassify an outcome and a check that only re-reads that script's own claim don't share the same blind spot — the identical pattern `010.08`'s seed-verification oracle already established for this repo

Every case below is read-only or side-effect-scoped to `.dev/logs/`, against either the already-committed milestone-07 app or a freshly spawned instance, so re-running the full table twice in a row is safe and idempotent.

**tools**: copy-pasteable, independent of whatever `12.06`/`.07`/`.08` automate:

```bash
# backend utility — batch replay against the real, already-committed milestone-07 app
env/bin/python -m easymcf &
curl -sf http://127.0.0.1:5000/api/v1/health
env/bin/python scripts/api_tester.py --case tests/backend/cases/selftest_api_tester.json --label 12.TC
cat .dev/logs/*-12.TC-api_tester.log
kill %1

# frontend utility — self-test against env-status; full batch is mixed-outcome
# by design (exercises all 3 classes), so exit code is non-zero — that's expected
env/bin/python scripts/ui_tester.py --case tests/frontend/checks/selftest_ui_tester.json --api-mode real --label 12.TC
# a true all-PASS smoke check runs the one passing case by name (see note 12.TC.07/.08)
env/bin/python scripts/ui_tester.py --case tests/frontend/checks/selftest_ui_tester.json \
    --name "selftest — env-status heading renders" --api-mode mocked --label 12.TC
cat .dev/logs/*-12.TC-ui_tester.log
ls .dev/logs/screenshots/

# oracle layer — independent hard-coded-expectation check
env/bin/python -m pytest -m backend -k selftest -v
env/bin/python -m pytest -m "frontend or e2e" -k selftest -v

# no-regression check against prior milestones
env/bin/python scripts/envcheck.py && env/bin/python -m pytest
env/bin/python scripts/resetdb.py --seed
```

### `12.EL.01` `scripts/_val_log.py`

```python
"""12.CK.05 — shared structured log writer for scripts/api_tester.py and
scripts/ui_tester.py: one JSON-lines record per case, appended as the run
progresses, so a downstream reader (human or the 12.EL.07/.08 oracle tests)
parses one log shape regardless of which script produced it. Pure logging —
this module never decides a process's exit code; that stays each caller's
own policy (implementation/REFERENCE.md's "no silent failures" convention),
so outcome-vs-exit-code logic never has two places to drift apart.

from __future__ import annotations

import json
import os
import time
from datetime import datetime, timezone

_SCRIPTS_DIR = os.path.dirname(os.path.abspath(__file__))
_REPO_ROOT = os.path.dirname(_SCRIPTS_DIR)
_LOGS_DIR = os.path.join(_REPO_ROOT, ".dev", "logs")


def log_path(tool: str, label: str = "adhoc") -> str:
    """<ts>-<label>-<tool>.log under .dev/logs/, per implementation/REFERENCE.md's
    <feature_id>.<subfeature_id> naming slot — label is the *caller's* task id
    (e.g. "09.09"), not this milestone's own, since 09-11 are the real callers."""

    ts = time.strftime("%Y%m%d%H%M%S")

def write_record(
    path: str,
    tool: str,
    case: str,
    outcome: str,
    duration_ms: int,
    expected: object = None,
    actual: object = None,
    detail: str | None = None,
    screenshot: str | None = None,
) -> None:
    """Append one JSON-lines record. outcome is PASS/FAIL/ERROR — see
    api_tester.py's/ui_tester.py's own classification logic for what each

        "case": case,

        "actual": actual,
```

### `12.EL.02` `scripts/api_tester.py`

Existing ad hoc mode (`_ad_hoc()`) and its CLI surface are untouched. `_run_case()` is split into a pure classifier plus the request call, so the classifier is independently testable and so the non-JSON-body case is caught in one place. `main()` gains `--label` and drops the old `"--case requires --name"` restriction.

```python
# new imports, alongside the existing ones
import time

sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))  # scripts/ itself
import _val_log  # noqa: E402


def _classify_response(case: dict, resp) -> tuple[str, object, object, str | None]:
    """PASS/FAIL/ERROR for one response against one case's expectations.
    ERROR is reserved for "the response can't be interpreted at all" (body
    isn't JSON when expected_body was supplied) — a value that parsed fine
    and simply didn't match is always FAIL, never ERROR."""
    expected_status = case.get("expected_status")
    expected_body = case.get("expected_body")

    actual_body = None
    if expected_body is not None:
        try:
            actual_body = resp.json()
        except ValueError:
            return "ERROR", expected_body, resp.text[:500], "response body is not valid JSON"

    if expected_status is not None and resp.status_code != expected_status:
        return "FAIL", expected_status, resp.status_code, None
    if expected_body is not None and actual_body != expected_body:
        return "FAIL", expected_body, actual_body, None
    return "PASS", None, None, None


def _run_case(case: dict, base_url: str) -> tuple[str, object, object, str | None]:
    """(outcome, expected, actual, detail) — a connection/timeout failure is
    ERROR, never FAIL, so an agent doesn't have to parse message text to tell
    "the endpoint isn't running" from "the endpoint returned the wrong thing"."""
    try:
        resp = requests.request(case["method"], base_url + case["path"], json=case.get("body"), timeout=10)
    except requests.RequestException as exc:
        return "ERROR", None, None, f"request error: {exc}"
    return _classify_response(case, resp)


def _report(case_name: str, outcome: str, expected, actual, detail: str | None) -> None:
    if outcome == "PASS":
        print(f"[PASS] {case_name}")
    elif outcome == "FAIL":
        print(f"[FAIL] {case_name} — expected {expected!r}, got {actual!r}")
    else:  # ERROR — stdout convention stays [FAIL], detail goes to stderr, per api_tester.py's existing style
        print(f"[FAIL] {case_name} — {detail}", file=sys.stderr)


def _case_batch(case_path: str, name: str | None, label: str) -> int:
    with open(case_path, "r", encoding="utf-8") as f:
        cases = json.load(f)
    if name is not None:
        cases = [c for c in cases if c["name"] == name]
        if not cases:
            print(f"[FAIL] no case named {name!r} in {case_path}", file=sys.stderr)
            return 1

    base_url = _base_url()
    log = _val_log.log_path("api_tester", label)
    exit_code = 0
    for case in cases:
        start = time.monotonic()
        outcome, expected, actual, detail = _run_case(case, base_url)
        duration_ms = int((time.monotonic() - start) * 1000)
        _report(case["name"], outcome, expected, actual, detail)
        _val_log.write_record(log, "api_tester", case["name"], outcome, duration_ms, expected, actual, detail)
        if outcome != "PASS":
            exit_code = 1
    return exit_code


def main() -> int:
    parser = argparse.ArgumentParser(description=__doc__, formatter_class=argparse.RawDescriptionHelpFormatter)
    parser.add_argument("--case", help="path to a tests/backend/cases/*.json file")
    parser.add_argument("--name", default=None, help="run only this case (default: every case in --case's file)")
    parser.add_argument("--label", default="adhoc", help="caller's feature/task id for the log filename, e.g. 09.09")
    parser.add_argument("method", nargs="?", help="HTTP method, ad hoc mode")
    parser.add_argument("path", nargs="?", help="request path, ad hoc mode")
    parser.add_argument("body", nargs="?", default=None, help="JSON request body, ad hoc mode")
    args = parser.parse_args()

    if args.case:
        return _case_batch(args.case, args.name, args.label)

    if not args.method or not args.path:
        parser.error("ad hoc mode requires METHOD and PATH")
    return _ad_hoc(args.method.upper(), args.path, args.body)
```

### `12.EL.03` `scripts/ui_tester.py`

Mirrors `api_tester.py`'s two-mode shape deliberately: an ad hoc `ROUTE SELECTOR` mode that opens a page and prints one selector's text/visibility (the frontend equivalent of "show me the response"), and a `--case FILE [--name NAME]` config-replay mode. Process/browser lifecycle is the only genuinely new piece — everything else follows `api_tester.py`'s pattern.

```python
#!/usr/bin/env python3
"""12.EL.03 — replay tests/frontend/checks/*.json UI-check configs standalone,
outside pytest, against a real `python -m easymcf` process this script spawns
itself via tests/_browser_support.py's spawn_app/terminate_app (unmodified).
Assertions follow ARCH-TEST-05's convention exactly: rendered text,
visibility, or attribute value — never a JS-internals check.

Two modes:

    # (a) ad hoc — open one route, print one selector's text + visibility
    python scripts/ui_tester.py / '[data-testid="env-status-heading"]'

    # (b) case-replay — run every check in a file (or one named check)
    python scripts/ui_tester.py --case tests/frontend/checks/selftest_ui_tester.json
    python scripts/ui_tester.py --case tests/frontend/checks/selftest_ui_tester.json \
        --name "env-status heading renders" --api-mode mocked
"""

import argparse
import json
import os
import sys
import tempfile
import time

from playwright.sync_api import TimeoutError as PlaywrightTimeoutError
from playwright.sync_api import sync_playwright

_SCRIPTS_DIR = os.path.dirname(os.path.abspath(__file__))
_REPO_ROOT = os.path.dirname(_SCRIPTS_DIR)
sys.path.insert(0, _SCRIPTS_DIR)
sys.path.insert(0, _REPO_ROOT)

from initdb import apply_schema  # noqa: E402
from resetdb import apply_seed  # noqa: E402
from tests._browser_support import spawn_app, terminate_app  # noqa: E402

_EXPECT_OPS = {
    "visible": lambda locator, value: (locator.is_visible() == value, value, locator.is_visible()),
    "text_equals": lambda locator, value: (locator.inner_text() == value, value, locator.inner_text()),
    "attribute_equals": None,  # dispatched separately — needs the attribute name too
    "count_equals": lambda locator, value: (locator.count() == value, value, locator.count()),
}


def _slug(name: str) -> str:
    return "".join(c if c.isalnum() else "-" for c in name.lower()).strip("-")


def _run_actions(page, actions: list[dict]) -> None:
    for step in actions:
        op = step["op"]
        locator = page.locator(step["selector"])
        if op == "wait_for":
            locator.wait_for(state="visible", timeout=step.get("timeout_ms", 10_000))
        elif op == "click":
            locator.click()
        elif op == "fill":
            locator.fill(step["value"])
        else:
            raise ValueError(f"unknown action op: {op!r}")


def _check_expect(page, expect: dict) -> tuple[bool, object, object]:
    locator = page.locator(expect["selector"])
    op = expect["op"]
    if op == "attribute_equals":
        actual = locator.get_attribute(expect["attribute"])
        return actual == expect["value"], expect["value"], actual
    handler = _EXPECT_OPS.get(op)
    if handler is None:
        raise ValueError(f"unknown expect op: {op!r}")
    return handler(locator, expect["value"])


def _run_check(browser, base_url: str, check: dict, label: str, log_path: str) -> str:
    case_name = check["name"]
    start = time.monotonic()
    page = browser.new_page()
    page_errors: list[str] = []
    page.on("pageerror", lambda exc: page_errors.append(str(exc)))

    outcome, expected, actual, detail = "PASS", None, None, None
    try:
        page.goto(base_url + check["route"], timeout=10_000)
        _run_actions(page, check.get("actions", []))
        if page_errors:
            raise RuntimeError(f"page error: {page_errors[0]}")
        for expect in check.get("expect", []):
            matched, expected, actual = _check_expect(page, expect)
            if not matched:
                outcome = "FAIL"
                break
    except (PlaywrightTimeoutError, RuntimeError) as exc:
        outcome, expected, actual, detail = "ERROR", None, None, str(exc)

    duration_ms = int((time.monotonic() - start) * 1000)
    screenshot = None
    if outcome != "PASS":
        screenshot = os.path.join(
            _REPO_ROOT, ".dev", "logs", "screenshots", f"{time.strftime('%Y%m%d%H%M%S')}-{label}-{_slug(case_name)}.png"
        )
        os.makedirs(os.path.dirname(screenshot), exist_ok=True)
        page.screenshot(path=screenshot)
    page.close()

    if outcome == "PASS":
        print(f"[PASS] {case_name}")
    else:
        print(f"[FAIL] {case_name} — {detail or f'expected {expected!r}, got {actual!r}'}", file=sys.stderr)

    _val_log.write_record(log_path, "ui_tester", case_name, outcome, duration_ms, expected, actual, detail, screenshot)
    return outcome


def _register_api_mock(page, fixtures_path: str | None) -> None:
    """ARCH-TEST-09's interception pattern, applied standalone. No fixtures
    file yet exists (07.EL.30/.32 — env-status makes no /api call), so an
    unmocked /api/** request falls through to the real backend (page.
    route(...).continue_()) rather than aborting — a stricter "fail on any
    unmocked call" behavior is deferred until milestone 09 ships a real
    tests/fixtures/api/*.json this script can point at (known limitation,
    Design section, `--api-mode mocked` self-test entry)."""
    fixtures: dict[str, dict] = {}
    if fixtures_path:
        with open(fixtures_path, "r", encoding="utf-8") as f:
            fixtures = json.load(f)

    def _handler(route):
        entry = fixtures.get(route.request.url.split("?")[0].split(base_url_placeholder := "", 1)[-1])
        if entry is None:
            route.continue_()
        else:
            route.fulfill(status=entry.get("status", 200), json=entry.get("body"))

    page.route("**/api/**", _handler)


def _case_batch(case_path: str, name: str | None, api_mode: str, api_fixtures: str | None, label: str) -> int:
    with open(case_path, "r", encoding="utf-8") as f:
        checks = json.load(f)
    if name is not None:
        checks = [c for c in checks if c["name"] == name]
        if not checks:
            print(f"[FAIL] no check named {name!r} in {case_path}", file=sys.stderr)
            return 1

    db_dir = tempfile.mkdtemp(prefix="easymcf-ui-tester-")
    db_path = os.path.join(db_dir, "easymcf.db")
    apply_schema(db_path)
    apply_seed(db_path)
    proc, base_url = spawn_app(db_path)
    log_path = _val_log.log_path("ui_tester", label)
    try:
        with sync_playwright() as p:
            browser = p.chromium.launch(headless=os.environ.get("HEADLESS", "1") != "0")
            try:
                exit_code = 0
                for check in checks:
                    outcome = _run_check(browser, base_url, check, label, log_path)
                    if outcome != "PASS":
                        exit_code = 1
                return exit_code
            finally:
                browser.close()
    finally:
        terminate_app(proc)


def _ad_hoc(route: str, selector: str) -> int:
    db_dir = tempfile.mkdtemp(prefix="easymcf-ui-tester-")
    db_path = os.path.join(db_dir, "easymcf.db")

def main() -> int:
    parser = argparse.ArgumentParser(description=__doc__, formatter_class=argparse.RawDescriptionHelpFormatter)
    parser.add_argument("--case", help="path to a tests/frontend/checks/*.json file")

    parser.add_argument("--api-mode", choices=["real", "mocked"], default="real")
    parser.add_argument("--api-fixtures", default=None, help="tests/fixtures/api/*.json, --api-mode mocked only")
    parser.add_argument("--label", default="adhoc", help="caller's feature/task id for the log filename, e.g. 09.09")
    parser.add_argument("route", nargs="?", help="ad hoc mode: route to open")
    parser.add_argument("selector", nargs="?", help="ad hoc mode: selector to inspect")
    args = parser.parse_args()
```

Oracle layer for `ui_tester.py`. `real`-mode checks are marked `e2e` (Playwright + real backend, matching what that mode actually exercises); the `mocked`-mode smoke check is marked `frontend` (mocked-`/api` semantics), even though both mechanically just shell out to the same subprocess with a different flag — the marker reflects what's being proven, not the mechanism, matching how `12.TC.07`/`.08` were scoped in Test cases.

```python
"""12.EL.08 — oracle for scripts/ui_tester.py's PASS/FAIL/ERROR classification
and screenshot capture (12.CK.03/.04). ui_tester.py spawns its own app
internally (12.EL.03), so this test needs no app_base_url fixture — it only
invokes the script as a subprocess and reads back its log + screenshot."""

from __future__ import annotations

import glob
import json
import os
import subprocess
import sys

import pytest

_REPO_ROOT = os.path.dirname(os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
_CHECKS_DIR = os.path.join(os.path.dirname(os.path.abspath(__file__)), "checks")


def _run_ui_tester(api_mode: str, label: str) -> tuple[int, list[dict]]:
    result = subprocess.run(
        [sys.executable, os.path.join(_REPO_ROOT, "scripts", "ui_tester.py"),
         "--case", os.path.join(_CHECKS_DIR, "selftest_ui_tester.json"),
         "--api-mode", api_mode, "--label", label],
        cwd=_REPO_ROOT, capture_output=True, text=True, timeout=60,
    )
    log_glob = os.path.join(_REPO_ROOT, ".dev", "logs", f"*-{label}-ui_tester.log")
    records = [json.loads(line) for line in open(sorted(glob.glob(log_glob))[-1], encoding="utf-8")]
    return result.returncode, records


@pytest.mark.e2e
def test_real_mode_outcomes_and_screenshots():
    exit_code, records = _run_ui_tester("real", "12.TC.real")
    by_name = {r["case"]: r for r in records}
    assert by_name["selftest — env-status heading renders"]["outcome"] == "PASS"
    fail_record = by_name["selftest — deliberately wrong expected heading text"]
    assert fail_record["outcome"] == "FAIL"
    assert os.path.exists(fail_record["screenshot"])
    error_record = by_name["selftest — nonexistent selector times out"]
    assert error_record["outcome"] == "ERROR"
    assert os.path.exists(error_record["screenshot"])
    assert exit_code != 0


@pytest.mark.frontend
def test_mocked_mode_wiring_smoke():
    """Known limitation (Design section): env-status makes no /api call, so
    this only proves --api-mode mocked doesn't error out wiring page.route()
    — not that a mocked response diverges from a real one. Closes once
    milestone 09 adds the first API-backed screen."""
    exit_code, records = _run_ui_tester("mocked", "12.TC.mocked")
    assert records[0]["outcome"] == "PASS"
    assert exit_code == 0
```
