## Scope

Add a **MCF** entry to the left nav, alongside the six existing destinations (Tracks, Posts, Leads, Offers, Applications, Automation), that opens an easyMCF-owned status page instead of embedding the live MCF site. The page shows a clear authenticated/not-authenticated indicator for the MCF session state known to easyMCF and includes a link that opens `https://www.mycareersfuture.gov.sg/` in a separate browser tab or window.

- all steps can be executed by an autonomous claude ai agent with access to terminal using re-runnable idempotent scripts, except any live MCF sign-in check a human explicitly chooses to perform under Workflow 8 and `ARCH-TEST-06`'s live tier
- **session source**: the indicator reads easyMCF's existing MCF session record and reports whether it is present, unexpired, and authenticated according to the same status fields the apply automation path already relies on. If no such record exists, or the record is expired or unauthenticated, the page shows a not-authenticated state and points the user to the existing session-establishment workflow.
- **website link**: the MCF website opens as an external top-level browsing context, using a normal hyperlink or equivalent `target="_blank"` behavior. This avoids iframe and webview scope entirely.
- **out of scope**
  - embedding the live MCF website in an `<iframe>`, webview, proxy frame, or any other in-app browser surface
  - capturing MCF session cookies from the opened website tab or replacing the existing manual MCF-session-upload flow in Workflow 8
  - scraping, parsing, or automating actions on the live MCF page opened by the link
  - any change to the search-by-keywords scraping pipeline or apply automation state machine
  - any change to `ARCH-NET-01`'s loopback bind or `ARCH-NET-03`'s allowed-outbound-destinations list, since this feature only links to the MCF origin already known to the release
  - single sign-on, credential sharing, or any mechanism that logs the user into MCF automatically without their own Singpass action. Singpass login itself stays manual and out of scope per REQ-APPLY-06.
  - live-site validation run unattended or by an agent on its own initiative. Any check against the real `mycareersfuture.gov.sg` origin is human-gated per `ARCH-TEST-06` and `CLAUDE.md`'s boundary.
- **closure**
  - **17.CK.01** clicking **MCF** in the nav opens an easyMCF-owned status page while every other nav destination remains reachable with one click
  - **17.CK.02** the page shows whether easyMCF has an active authenticated MCF session available, with distinct authenticated and not-authenticated states
  - **17.CK.03** the page includes a link that opens `https://www.mycareersfuture.gov.sg/` in a separate top-level browser context
  - **17.CK.04** the feature does not add an in-app live-site embed, webview, proxy, session capture path, or automatic Singpass flow
  - **17.CK.05** the existing manual MCF-session-upload flow in Workflow 8 keeps working unmodified

## Design

### MCF status page

The MCF nav destination is an easyMCF page that reports session status and offers an external link. It deliberately uses the browser's normal top-level navigation for MCF because the release only needs a visible path to the website and a local status indicator. It does not need to render or control the live MCF site inside easyMCF.

**implementation decision** - Use the existing MCF session record as the status source. The page should not try to infer login state from the external MCF tab because that would require cross-site inspection or new browser automation outside this feature's scope.

**deviation** - This adds a seventh navigation destination, but the destination is a local status page rather than a live MCF surface. That is the scoped-down option 2 direction for this feature.
